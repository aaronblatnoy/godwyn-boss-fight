# Hero render — human launch on the Linux server only

Requires headless Blender 5.2.1-compatible Cycles with NVIDIA drivers/OptiX. Keep the repository, inputs, scripts, logs and outputs under `~/godwyn-boss-fight/` (CLAUDE.md). **Do not launch the full clip on the Mac. No network operations are performed by this script.**

From the server shell, run this one line:

```sh
cd ~/godwyn-boss-fight && mkdir -p renders/astra/cine && blender --background --factory-startup --debug-cycles --python-exit-code 1 --python scripts/astra_cine_hero_render.py -- --device AUTO --output "$PWD/renders/astra/cine/hero" --width 1920 --height 1080 --samples 512 --frame-start 1 --frame-end 90 > "$PWD/renders/astra/cine/hero_launch.log" 2>&1
```

- `AUTO`: prefer **OPTIX**, then CUDA, then Metal. All visible matching GPUs enabled; CPU disabled. Preserve the server’s OS quarantine; the script also excludes a reported PCI `07:00` device. Set `--device OPTIX` to require OptiX strictly, or `CUDA` / `METAL` explicitly. An unavailable explicit backend **fails nonzero**. CPU requires both `--device CPU --allow-cpu`; it is never an automatic fallback.
- Default animation is the motion track’s **final, complete and gate-approved** `models/astra_xslash_v2_final_wip.blend`, still overridable with `--blend`. Defaults read **current files at runtime**: `models/astra_xslash_v2_final_wip.blend` and `models/astra_character_v2.blend`. Override with `--blend` and `--character-blend`. No snapshots/copies/saves. Fresh character objects are assembled in memory on the unchanged animation rig; incompatible bone/rest transforms fail before rendering.
- Keep outputs under the project’s `renders/astra/cine/`. Change `--output`, `--width`, `--height`, `--samples`, `--frame-start`, `--frame-end`, or `--frame-step` as needed. `--frames 27,41,90` selects individual stills instead. Mac runs are hard-limited to **three frames**, with 512px Metal tiles to reduce memory pressure. `--verify-idempotence` checks two identical treatment applications before rendering.
- **KNOWN FRAGILITY — blue is script-applied.** Loading the fresh character without this override can silently produce pale blue; loading the saved animation without updating its old tint can produce the superseded brighter blue. Shared code applies the current art-directed coefficients to the two cloth/trim materials, preserves gold using the existing metallic mask, and replaces existing tint values without multiplying twice.
- **ART-DIRECTED TINT: rung B `(0.02, 0.03, 0.23)` is now the shared hero/default tint.** It deliberately supersedes BOTH the old `(0.025, 0.20, 0.62)` multiplier and a naive use of CLAUDE.md’s `(0.00, 0.03, 0.23)` base color. A multiply/mix over a baked atlas is not a base-color assignment; lighting and AgX further change displayed RGB. B was selected from three controlled frame-41 renders: darkest overall readable silhouette, with one short weak left-edge notch common to A/B/C. This is not a full-animation silhouette guarantee. Override explicitly with `--tint R G B`; measurements/images are in `renders/astra/cine/indigo_ladder/`.
- **PRECONDITION — recheck historical material gaps against the final character:** historical skin emission gap **0.014 versus SPEC 2.5**; the current character audit now reads **2.5 with texture-driven emission color**, so review effective emission rather than assume the old value still applies (do not resolve by changing lighting); no engraving displacement connection; main royal-blue cloth and undersleeves have **zero sheen weight** (secondary midnight silk is **0.18**, so not all cloth is zero); hair has **zero anisotropy and no strand shader**. These require source-owner review, not automatic changes by this launcher.
- Approved treatment is imported from `astra_cine_render.py`. Haze defaults **off**; do not enable `--haze` until its separate gate passes.
- Output: `renders/astra/cine/hero/hero_f001.png` … `hero_f090.png`, 16-bit PNG sequence, plus `hero_metrics.json` with input hashes, devices and per-frame times. The sequence is not automatically video-encoded. Console evidence is in `renders/astra/cine/hero_launch.log`.
- M1 planning figure: roughly **87–150 seconds/frame** at 1080p final quality (historical, pose/cache dependent; a warmed settle previously took 42s). The latest corrected-blue verification took **208.6s including image save**, so 150s is not a ceiling. Server allowance **15–30 minutes without haze** extrapolates the supervisor’s approximately 10× estimate. **NOTHING has been benchmarked on the RTX 3060 Tis; this is extrapolated, not measured.** New hair/materials and haze can change it substantially. **Each RTX 3060 Ti has only 8 GB; memory does NOT pool across the two cards. The scene must fit in 8 GB per card.**

If interrupted, resume by setting `--frame-start` to the first missing frame. Existing requested PNGs are overwritten; preserve/rename the prior metrics file before resuming if its timings are needed.
